# Yarn Workspaces example — validation fixture for the future Yarn `WorkspaceAdapter`

Real Yarn 4 (Berry) via corepack (`corepack use yarn@stable`, `corepack yarn install`), with a `"workspaces": ["packages/*"]` field and a real `"@example/core": "workspace:*"` dependency. See [docs/monorepo_architecture.md](../../../docs/monorepo_architecture.md) §7: every future monorepo adapter must be proven against a repository actually generated by that tool's own tooling, not a fixture that guesses at the config format.

## What's here

- `package.json` — `workspaces: ["packages/*"]`, real `packageManager` field.
- `packages/core` — `@example/core`, no dependencies.
- `packages/billing-service` — `@example/billing-service`, depends on `@example/core` via `"workspace:*"`.
- `yarn.lock` — the real lockfile Yarn produced. Its `@example/billing-service@workspace:...` entry lists `"@example/core": "workspace:*"` as a dependency and resolves it via `linkType: soft` — that's Yarn's own workspace-link resolution, not written by hand.
- `graph-output.json` — the real output of `yarn workspaces list --json`, checked in as the snapshot a future adapter's test suite should assert against.

`.pnp.cjs` and `.yarn/install-state.gz` (Yarn's Plug'n'Play install artifacts, regenerated on every `install`) are gitignored, same treatment as `node_modules` elsewhere in this directory — they're install output, not source config a `WorkspaceAdapter` should need to read.

## What a real `YarnWorkspacesAdapter` should reproduce

Per `docs/monorepo_architecture.md` §4, `YarnWorkspacesAdapter.buildGraph()` run against this directory should produce:

```ts
{
  tool: 'yarn',
  projects: [
    { name: '@example/core', kind: 'package', path: 'packages/core' },
    { name: '@example/billing-service', kind: 'package', path: 'packages/billing-service' },
  ],
  edges: [
    { from: '@example/billing-service', to: '@example/core', kind: 'depends_on' },
  ],
}
```

Regenerate `.pnp.cjs`/`.yarn` with `corepack yarn install` from this directory if you need to re-run `yarn workspaces list` yourself.
