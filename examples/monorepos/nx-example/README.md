# Nx example — validation fixture for the future Nx `WorkspaceAdapter`

Generated with `npx create-nx-workspace@latest nx-example --preset=ts --interactive=false --nxCloud=skip --packageManager=npm --skipGit=true`, then extended with two real libraries and a real dependency between them — not hand-written. See [docs/monorepo_architecture.md](../../../docs/monorepo_architecture.md) §7: every future monorepo adapter must be proven against a repository actually generated by that tool's own scaffolding, not a fixture that guesses at the config format.

## What's here

- `nx.json`, `tsconfig.base.json` — real Nx workspace config, untouched from what `create-nx-workspace` produced.
- `packages/core` — a library generated with `npx nx g @nx/js:library packages/core`.
- `packages/billing-service` — a second library (`npx nx g @nx/js:library packages/billing-service`), hand-edited to `import { core } from '@org/core'` and declare `@org/core` as a real `package.json` dependency — the one deliberate addition, needed so there's a real `depends_on` edge for the adapter to detect.
- `graph-output.json` — the real output of `npx nx graph --file=graph-output.json` against this workspace, checked in as the snapshot a future adapter's test suite should assert against. The relevant part:
  ```json
  "@org/billing-service": [{ "source": "@org/billing-service", "target": "@org/core", "type": "static" }],
  "@org/core": []
  ```
  That edge was produced by Nx's own dependency graph, not written by hand.

## What a real `NxAdapter` should reproduce

Per `docs/monorepo_architecture.md` §4, `NxAdapter.buildGraph()` run against this directory should produce:

```ts
{
  tool: 'nx',
  projects: [
    { name: '@org/core', kind: 'library', path: 'packages/core' },
    { name: '@org/billing-service', kind: 'library', path: 'packages/billing-service' },
  ],
  edges: [
    { from: '@org/billing-service', to: '@org/core', kind: 'depends_on' },
  ],
}
```

`node_modules` is not committed (see `.gitignore`); regenerate it with `npm install` from this directory if you need to re-run `npx nx graph` yourself.
